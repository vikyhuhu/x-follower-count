# X 粉丝数

Chrome Manifest V3 扩展，显示 X 页面已加载的账号数据：粉丝数、关注关系、账号年龄及统一详情卡。**1.2.5**。与 X / Twitter 无官方关联。

## 安装和更新

**最新版：[下载 1.2.5 安装包](https://github.com/vikyhuhu/x-follower-count/releases/download/v1.2.5/x-follower-count-1.2.5.zip)** · [版本说明](https://github.com/vikyhuhu/x-follower-count/releases/tag/v1.2.5)

### 首次安装

1. 下载上方安装包，解压到准备长期保留的文件夹。
2. 打开 `chrome://extensions`，开启开发者模式。
3. 点击「加载已解压的扩展」，选择包含 `manifest.json` 的解压文件夹。
4. 刷新已打开的 X 页面。

也可通过 **Code → Download ZIP** 下载源码或克隆仓库；使用源码时，加载项目内的 **extension** 文件夹。

### 更新并保留已有粉丝趋势记录

适用于通过「加载已解压的扩展」安装的用户：

1. 在 `chrome://extensions` 找到「X 粉丝数」，进入「详细信息」，确认当前加载的文件夹路径。
2. 下载最新版安装包，先解压到临时文件夹。
3. 将解压后的插件文件复制到**原来加载的文件夹**，覆盖对应文件。`manifest.json` 应仍位于原文件夹根目录，不要把新版文件夹整体套在里面。原文件夹名称即使带旧版本号，也无需改名。
4. 回到扩展管理页，点击该插件的「重新加载」，确认版本为 **1.2.5**，再刷新 X 页面。
5. 打开曾有记录的账号详情卡，确认近7天趋势中的历史日期仍在。

**不要先移除插件再安装，不要改为加载另一个文件夹，也不要点击「清除全部趋势记录」。** 更新时使用同一浏览器配置文件、原加载路径和原扩展 ID，已有趋势记录和设置会继续保留。

趋势记录存放在 Chrome 的扩展本地存储中，不在安装包里；复制插件文件夹不等于备份记录。[Chrome 官方说明](https://developer.chrome.com/docs/extensions/reference/api/storage)明确指出，移除扩展会清除其本地数据。更新后仍按30天保留期、账号上限和存储预算淘汰较早记录。

独立安装包与商店上传共用一个 ZIP，`manifest.json` 位于根目录；商店后台直接上传 ZIP。

## 功能

- 信息流标签位于账号和发布时间后；用户列表及侧边推荐标签位于 @账号下方，空间不足时换行，保留名称和账号的可读空间。标签包含粉丝数、互相关注／关注了你／你已关注、账号年龄。粉关比只在详情卡中显示，小于1显示一位小数（如 `0.8:1`），大于等于1取整；关注数为零显示 `0`，缺失数据显示「—」。注册未满90天显示橙色「新号」，90天至未满1年以淡琥珀色显示时长（如「8个月」），满1年后以灰色显示时长（如「3年8个月」），不增加额外提示文字。
- 粉丝数量分色：0–999灰、1,000–9,999蓝、10,000–99,999紫、100,000–999,999橙、100万及以上红。亮暗主题分别配色。
- 任意标签悬停约250毫秒、点击或键盘聚焦，打开同一详情卡。支持 Tab、Enter、Esc；关闭按钮可用键盘操作。卡片优先完整展示，空间不足时向屏幕内平移，仅在视口本身放不下完整内容时允许内部滚动。
- 详情卡显示关注数、精确粉丝数、带突出标签的粉关比、总发帖数、账号年龄、UTC注册时间。关系标签位于名称旁；认证状态、含图片/视频的帖数、专业账号类别、个人网站默认开启，可在工具栏分别关闭。类别是账号自己选择的专业类别，缺失时不显示；媒体计数是 X 返回的含图片/视频的帖数，不是图片文件数量。**总发帖数不是全历史原创数**。未知字段显示「—」，不推断成零。
- **本机粉丝趋势**新安装默认开启，可在工具栏关闭；升级保留已有设置。记录已加载账号的粉丝快照；近七个北京时间自然日的每日最后一次观察值显示为柱状图，首个观察日靠左、数字直接显示，中间缺失日留空。柱高按该账号自身数值范围缩放，缩放时显示提示；至少有两天记录时，标题旁以小标签显示首末记录的净变化及相对首日的变化百分比（四舍五入保留两位小数），例如 `▲418（幅度1.71%）`；红色▲表示上涨，绿色▼表示下跌，方向只标记一次，持平使用中性色。起始值为零且发生增长时，百分比显示「—」。仅一天记录时说明趋势仍在积累；没有记录时只显示标题和空图。
- 「含图片/视频的帖数」紧跟总发帖数，字段名称保持单行；计数后附媒体帖数占总发帖数的整数百分比，例如 `1,581（18%）`。总发帖数缺失或为零时不显示占比。
- 动态加载、用户列表、节点复用、亮暗主题及窄屏布局。关系只针对当前登录账号，检测账号切换后清空页面缓存。

## 1.2.5 更新

- 媒体帖数附整数占比，粉关比在详情卡中突出显示。
- 粉丝趋势按账号自身数值范围缩放，以红色▲／绿色▼显示首末记录净变化和两位小数百分比；单日记录显示积累说明。
- 详情卡优先完整放入屏幕，仅在窗口本身太矮时滚动。
- 本机趋势账号上限提高至10,000，仍受30天保留期和8 MiB预算限制。
- 90天至未满1年的号龄时长使用淡琥珀色，新号橙色、满1年灰色；关注关系配色保持一致。

## 数据和权限

只使用 `storage` 权限，页面注入范围仅为 HTTPS `x.com`、`www.x.com`、`twitter.com`、`www.twitter.com`。Chrome最低版本111。

只解析页面本身已发生的、明确允许的用户／时间线读取响应（GET 或 POST）。不额外查询账号，不读取请求头、凭证或 Cookie，不解析私信接口、不提取或保存帖子正文，不上传数据，无广告和遥测。账号详情和关注关系仅保存在页面内存。

记录开启时，本机仅持久保存用户 ID、观察时间与粉丝数，保留30天、最多10,000个账号、预算8 MiB，超限淘汰较早记录。关闭后停止新记录及趋势展示，已有快照可清除或保留到期；工具栏支持确认清除全部记录。升级自动移除旧版存储的资料和帖子样本。

完整说明见 [隐私政策](PRIVACY.md)，也可从工具栏打开离线隐私页面。趋势是已观察数据，不是完整历史；颜色和粉关比不代表账号质量。

## 使用边界与排查

X 的字段或页面结构可能变化，缺失字段不猜测。正文 @提及及没有独立用户链接的引用卡片不加标签。网络桥接运行于页面环境，可被页面干预，显示不是独立认证的数据。

1.2.1 修复首页标签及趋势不显示：X 的 HomeTimeline 是 POST 读取查询，现按允许的读取接口名称识别 GET／POST，仍忽略私信、认证和写操作。不读取请求正文、不增加请求。

1.2.4 补充支持个人主页的 UserOriginalsTimeline、Explore 的 ExplorePage，以及主页回复、转发、文章使用的 UserRepliesTimeline、UserRepostsTimeline、UserArticlesTweets 读取响应。推荐主列表与侧栏使用不同接口；遗漏主列表接口时，仅同时被侧栏加载的账号能获得标签。推荐卡片统一按账号识别，不依赖页面路径或「Who to follow」标题文本。冷加载回归覆盖 GET／POST、不同账号的主列表与侧栏、页面切换复用卡片及滚动后新增卡片。

已排查首页、Explore 各分类、个人主页、Follow／Creators for you、搜索、通知、帖子详情、用户关系列表、Lists 和 Communities 的账号推荐入口。具体入口、读取接口及真实页面验证范围见 [推荐页面覆盖表](docs/recommendation-surfaces.md)。

若没有显示，请检查插件已启用、站点访问允许 X，并刷新页面。重新加载扩展会使旧页面脚本失效；1.2.1已增加安全退出，更新后仍需刷新 X 才能运行新脚本。Chrome错误页的历史记录不会自动清空，可手动清除后观察是否再发生。

反馈问题请提供脱敏结构，勿提供请求头、Cookie、凭证或完整 HAR。

## 开发、验证和打包

原生 JS / CSS，无生产依赖和构建步骤。Node测试使用内置测试工具；浏览器验证使用 Python Playwright 与临时 Chrome 配置，全部页面和账号数据为合成数据。

```sh
pnpm test
python3 -m venv .test-venv
.test-venv/bin/python -m pip install -r requirements-dev.txt
.test-venv/bin/python -m playwright install chromium
.test-venv/bin/python tests/browser_test.py
.test-venv/bin/python tests/surfaces_browser_test.py
.test-venv/bin/python tests/card_browser_test.py
.test-venv/bin/python tests/privacy_browser_test.py
pnpm package
```

使用已有 Python Playwright 时可运行 `pnpm test:browser`。支持 `CHROMIUM_EXECUTABLE` 指定浏览器，`EXTENSION_UNDER_TEST` 指定待测解压目录。测试覆盖 Fetch／XHR 原始响应保留、无额外请求、关系、年龄、布局、键盘、图表、重启持久化、新安装全部默认开启、关闭和升级偏好保留、清除和失效上下文保护。1.2.4 新增推荐、书签与喜欢读取响应的冷缓存回归，以及列表名称、账号和标签在窄屏下的布局检查。1.2.4 修复曾重新加载到浏览器，在真实登录 X 的首页、侧边推荐、Who to follow、Creators for you、关注列表、书签及喜欢页面确认标签显示，侧边推荐名称和账号保留独立行。验证范围是当时已加载的账号；合成测试和抽样实测不能代替所有真实页面的兼容性检查。

1.2.5 验证：31项 Node 测试和解压安装包的四套浏览器回归通过，覆盖媒体占比、涨跌／持平／零基数、完整卡片定位、粉关比标签、号龄配色、记录保留与较小存储配额。实际登录 X 已抽样确认占比、趋势、卡片及三档号龄配色；实际配额兼容由合成测试验证。

打包命令生成 `dist/x-follower-count-1.2.5.zip`，供本地解压加载及 Chrome Web Store 上传共用。商店提交材料与后台填写说明见 [发布准备](docs/chrome-web-store.md)。
